# Швидкий старт

Встановити бібліотеку, відкрити сесію, поставити реєстру три справжні запитання і коректно закрити
сесію. Спершу програма, далі — розбір кожного її рядка.

## Встановлення

```xml
<dependency>
  <groupId>io.github.epptools</groupId>
  <artifactId>epptools-sdk</artifactId>
  <version>1.1.2</version>
</dependency>
```

Або Gradle:

```groovy
implementation 'io.github.epptools:epptools-sdk:1.1.2'
```

Зовсім без системи збирання? Клонуйте репозиторій, прив'язавшись до тегу релізу, і скомпілюйте
вихідні файли прямо у власне дерево — розв'язувати залежності не треба, бібліотека не має жодної:

```bash
git clone --branch v1.1.2 https://github.com/epptools/java-sdk
javac --release 8 -d out $(find java-sdk/src/main/java -name '*.java')
```

**Потрібна Java 8 або новіша.** TLS бере з `javax.net.ssl`, XML — з `javax.xml`; обидва входять до
JDK, тож більше додавати нічого не треба.

## Що потрібно, перш ніж запускати

| Що | Звідки береться |
|---|---|
| Хост і порт | Ваш обліковий запис. Порт — `700`, якщо вам не сказали інакше. |
| Ваш clID | Ваш ідентифікатор реєстратора, напр. `EXAMPLE`. |
| Пароль | Видається з обліковим записом, змінюється через `login()` — див. [Сесія](session.md). |
| Сертифікат CA реєстру | Лише там, де точка підключення подає сертифікат від власного приватного CA реєстру. Багато реєстрів подають звичайний сертифікат, якому довіряють браузери, і тоді налаштовувати нічого не потрібно. Запитайте, який ваш випадок, і набір `.pem`, якщо він потрібен. |
| Адреса відправлення у списку дозволених | Багато реєстрів вимагають, щоб публічна IP-адреса вашого сервера була зареєстрована для цього clID, інакше вхід відхиляється з 2200. |

## Уся програма

Збережіть її як `EppFirstRun.java`, підставте значення на початку і запустіть. На Java 11 і
новішій достатньо `java -cp epptools-sdk-1.1.2.jar EppFirstRun.java`; на 8 спершу скомпілюйте її
через `javac -cp epptools-sdk-1.1.2.jar EppFirstRun.java`.

```java
import com.epptools.sdk.Client;
import com.epptools.sdk.Config;
import com.epptools.sdk.Response;
import com.epptools.sdk.exception.EppException;

import java.util.Arrays;
import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;

public final class EppFirstRun {

    public static void main(String[] args) {
        Config config = Config.builder("epp.registry.example", "EXAMPLE", "your-secret")
                .lang("en")                              // мова повідомлень результату, якщо привітання її перелічує
                // .caFile("/etc/epp/registry-ca.pem")   // лише для приватного CA або самопідписаного сертифіката
                .build();

        // Client реалізує AutoCloseable, а close() роз'єднує, тож try-with-resources звільняє сокет
        // на кожному виході з блоку — зокрема на шляхах, де до logout() так і не дійшло.
        try (Client client = new Client(config)) {
            Response greeting = client.connect();
            System.out.println("server: " + or(greeting.value("svID"), "unnamed"));

            Response login = client.login();
            for (Map<String, String> event : login.securityEvents()) {
                System.err.println("login " + or(event.get("level"), "warning")
                        + " (" + or(event.get("type"), "custom") + "): " + event.get("text"));
            }

            Map<String, Object> feeQuery = new LinkedHashMap<String, Object>();
            feeQuery.put("create", 1);
            Response check = client.domain().check(Arrays.asList("example.com.ua"), feeQuery, null);

            if (Boolean.TRUE.equals(check.isAvailable("example.com.ua"))) {
                System.out.println("example.com.ua is available");
                System.out.println("  create, 1 year: "
                        + or(check.feeFor("example.com.ua", "create", 1), "not quoted")
                        + " " + or(text(check.fees().get("_currency")), ""));
            } else {
                System.out.println("example.com.ua is taken: "
                        + or(check.unavailableReason("example.com.ua"), "no reason given"));

                Response info = client.domain().info("example.com.ua");
                System.out.println("  sponsor: " + or(info.sponsor(), "-"));
                System.out.println("  expires: " + or(info.expiryDate(), "-"));
                System.out.println("  status:  " + join(info.statuses()));
                System.out.println("  ns:      " + join(info.nameservers()));
            }

            Response balance = client.balance();
            System.out.println("available credit: " + or(balance.availableCredit(), "-"));

            client.logout();
        } catch (EppException e) {
            System.err.println("EPP error: " + e.getMessage());
            System.exit(1);
        }
    }

    private static String or(String value, String fallback) {
        return value == null || value.isEmpty() ? fallback : value;
    }

    private static String text(Object value) {
        return value == null ? null : value.toString();
    }

    private static String join(List<String> values) {
        return values.isEmpty() ? "-" : String.join(", ", values);
    }
}
```

Очікуваний вивід на живому обліковому записі, коли ім'я зареєстроване кимось іншим:

```
server: Registry EPP Server
example.com.ua is taken: In use
  sponsor: ACME
  expires: 2027-04-01T09:15:00Z
  status:  ok
  ns:      ns1.example.com.ua, ns2.example.com.ua
available credit: 12500.00
```

Ніщо в цій програмі нічого не змінює і нічого не коштує. `check`, `info` та запит балансу — усі
лише читають, і саме тому вони правильні як перші команди: тільки їх безпечно повторювати наосліп.

## Рядок за рядком

Уся бібліотека живе в пакеті `com.epptools.sdk`: `Client`, `Config` і `Response` у корені, винятки —
у `com.epptools.sdk.exception`. Підключати більше нічого не потрібно, бо залежностей немає.

### `Config.builder(host, clid, password)`

Налаштування підключення. `builder()` бере три значення, без яких сесії немає, — хост, clID і
пароль, — а кожен наступний крок має значення за замовчуванням, тож для старту досить короткого
ланцюжка:

- **`host`**, **`clid`** та **`password`** не мають корисних значень за замовчуванням. Порожній
  `host`, порожній `clid` або відсутній пароль спричиняють `ConfigException` уже з `build()`;
  порожній пароль — з `login()`, ще до того, як байт потрапить у канал передачі.
- **`caFile`** потрібен лише там, де точка підключення подає сертифікат, виданий власним приватним
  CA реєстру: такого CA немає в жодному сховищі довіри, тож із перевіркою вузла, залишеною у
  правильному стані за замовчуванням, рукостискання без нього не вдасться. Без `caFile` клієнт
  довіряє власному сховищу JDK, і для сертифіката, якому браузери довіряють самі, це правильна
  поведінка.
- **`port`** за замовчуванням `700`. `lang` за замовчуванням `en`. Усе інше розібрано поле за полем
  у [Сесії](session.md).

Не тримайте пароль у файлі. Читайте його зі змінних середовища або зі свого сховища секретів; у
прикладі він виписаний лише для того, щоб програма була повною.

### `new Client(config)`

Створення клієнта нічого не відкриває. Ви отримуєте об'єкт; сокет буде далі. Другий необов'язковий
аргумент приймає власний транспорт, а третій — логер, див. [Сесія](session.md).

### `try (Client client = new Client(config))`

`Client` реалізує `AutoCloseable`, а його `close()` роз'єднує, тож блок try-with-resources закриває
сокет за будь-яких обставин, зокрема на шляхах, де до `logout()` так і не дійшло. У Java немає
деструктора, на який можна було б покластися, тож це — або явний `disconnect()` у `finally` — єдине,
що звільняє сесію. Незакрита сесія рахується у вашому обмеженні одночасних сесій, доки реєстр не
завершить її за тайм-аутом.

### `Response greeting = client.connect();`

Відкриває TLS-сокет і читає незапитане `<greeting>` сервера — перше, що надсилає сервер EPP
(RFC 5730). Привітання перелічує простори імен об'єктів і розширень, які підтримує цей сервер, а
`login()` повертає їх назад, тож сесію ніколи не відхилять за оголошення сервісу, якого сервер не
пропонує.

`connect()` повертає привітання як [`Response`](responses.md). `greeting.value("svID")` читає з
нього ім'я сервера. Якщо перший кадр не є привітанням, `connect()` спричиняє `ConnectionException`,
а не приймає те, що надійшло, за перелік сервісів.

### `Response login = client.login();`

Надсилає `<login>` з вашим clID і паролем, версією протоколу, мовою та переліком сервісів, узятим із
привітання. Повертає відповідь на вхід.

### Цикл `securityEvents()`

Там, де сервер пропонує розширення безпеки входу (RFC 8807), вхід несе невеликий блок, що
ідентифікує цього клієнта, а сервер відповідає всім, що радить виправити в цій сесії: клієнтський
сертифікат, який добігає кінця, застаріла версія TLS, набір шифрів, який не є AEAD.

На здоровій сесії перелік порожній, тож ставтеся до будь-якого запису як до того, на що треба
зреагувати. Кожен запис завжди несе `text`; `type` і `level` присутні, коли сервер їх надіслав —
звідси перевірка на `null` перед друком. Найчастіша подія — сертифікат, що спливає протягом
наступних 30 днів; альтернатива тому, щоб дізнатися про це тут, — дізнатися вранці, коли входи
припиняться.

### `client.domain().check(Arrays.asList("example.com.ua"), feeQuery, null)`

`domain()` повертає обробник доменних команд; `check()` надсилає `domain:check` (RFC 5731) і
повертає відповідь. Другий аргумент — карта тарифів — додає до неї запит ціни за RFC 8748, тож одне
коло обміну відповідає і на «чи вільне», і на «скільки коштувало б». Третій аргумент — валюта, у якій
ви хочете отримати ціну; `null` означає «у власній валюті реєстру».

Запит ціни безплатний і нічого не змінює. Повну форму таблиці цін, а також те, як перетворити те
саме розширення на **обмеження** суми, яку може списати змінна операція, див. у
[Балансі](balance.md).

### `check.isAvailable("example.com.ua")`

Повертає `Boolean`: `true`, `false` або `null`, коли відповідь про це ім'я нічого не сказала. Саме в
трьох варіантах і суть: звернення до карти доступності за ключем, який ви написали з помилкою, теж
дає `null`, а ці дві відповіді не мають виглядати однаково в рядку перед реєстрацією.

Порівнюйте через `Boolean.TRUE.equals(...)`, а не розпакуванням у `boolean`: розпакування `null`
спричиняє `NullPointerException` саме там, де програма мала б побачити третій варіант.

Порівняння не залежить від регістру, тож ім'я, набране в мішаному регістрі, все одно збігається.

### `check.feeFor("example.com.ua", "create", 1)`

Наведена ціна однієї операції за один період, як точний десятковий **рядок**, або `null`, коли
відповідь не несла такої ціни. Ніколи не приводьте його до `double` перед обчисленнями —
користуйтеся `BigDecimal` або цілими в дрібних одиницях. `fees().get("_currency")` — валюта, у якій
наведено всю відповідь.

Суми в цьому посібнику наведено для прикладу, це не тариф реєстру.

### `check.unavailableReason("example.com.ua")`

Власне формулювання реєстру про те, чому ім'я недоступне — `In use`, `Reserved` — або `null`, коли
воно доступне чи коли реєстр не назвав причини.

### `client.domain().info("example.com.ua")`

`domain:info` повертає повний запис імені, яке вам дозволено бачити. Програма надсилає його лише в
гілці, де ім'я зайняте: `info` для неіснуючого імені відхиляється з 2303, і це надходить як
`ObjectDoesNotExistException`.

`sponsor()`, `expiryDate()`, `statuses()` та `nameservers()` — іменовані аксесори, тож ви ніколи не
звертаєтесь до карти за рядком, який довелося вгадувати. `expiryDate()` повертає власний рядок
реєстру рівно таким, яким його надіслали. Кожен аксесор перелічено у [Відповідях](responses.md).

`nameservers()` охоплює обидві моделі делегування EPP — посилання на об'єкт хоста або ім'я з
вбудованими glue-адресами — тож перелік правильний, хоч би яку з них використовував цей реєстр.

### `client.balance()`

Баланс облікового запису реєстратора через розширення балансу реєстру. `availableCredit()` — те, що
ви ще можете витратити: баланс плюс будь-яка кредитна лінія, знову ж таки як точний десятковий
рядок. Див. [Баланс](balance.md).

### `client.logout();`

Завершує сесію. Сервер відповідає 1500 і закриває з'єднання. Сесія, обірвана без виходу, все одно
рахується у вашому обмеженні одночасних сесій, доки не спрацює тайм-аут, тож виходьте дорогою повз.

### `catch (EppException e)`

Кожен збій, який спричиняє ця бібліотека, розширює `EppException`, тож один catch охоплює все:
поганий аргумент, збій TLS, відмову реєстру. Усі вони неперевірювані, тож жоден підпис методу не
несе `throws`, і ніщо не примусить вас перехопити їх раніше, ніж ви самі захочете. Ловіть підкласи
там, де відрізняється правильний наступний крок: 2104 означає зупинити пакет і поповнити рахунок,
2302 — обрати інше ім'я. Повна таксономія — у [Помилках](errors.md).

Оскільки всі вони неперевірювані, ніщо не примушує вас писати цей catch. Пишіть його однаково:
альтернатива — робітник надання послуг, який помирає на 2303.
